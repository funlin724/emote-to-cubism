# 如何从自己的游戏中提取基础密钥

> 本仓库**不包含、也不提供**任何游戏的密钥。本文描述在**你合法持有的
> 游戏副本**上自行定位密钥的一般方法。仅限个人研究/互操作用途。

## 背景

MzS 容器的完整密钥 = 基础密钥串 + 文件全名（含扩展名）。基础密钥串是
每个游戏唯一的常量（通常 10~20 个 ASCII 字符），硬编码在游戏主程序内。

## 方法一：静态字符串搜索（通常 10 分钟内可完成）

1. 用二进制编辑器/反汇编工具（如 Ghidra、x64dbg、strings）打开游戏
   主程序 EXE；
2. 搜索**资源归档文件名字符串**（如 `*_info.psb.m`、`*_body.bin`、
   `<Documents>\My Games\<引擎名>\...` 等路径常量）——引擎的归档路径表
   附近就是密钥的典型存放位置；
3. 在这些字符串邻近区域寻找长度 10~20 的无规律 ASCII 串；
4. 验证：把候选串 + 某个 `*_info.psb.m` 文件名拼接，用
   `tools/mzs_decrypt.py --key <候选串> <文件>` 解密，**成功判据 = 输出是
   `PSB\0` 开头的标准 PSB**。按容器世代中间形态不同：
   新世代（`mzs\0`）密文解密后是 Zstd 流；老世代（`mdf\0`，2015 前后）
   是 Zlib 流（首字节 `0x78`）、尾部带 Adler32——工具按魔数自动分派，
   无需手工区分。密钥错误时新世代会报 Zstd 解压失败、老世代会报
   "解密结果不是 Zlib 流"。
5. 交叉验证：用第二个归档文件重复验证（排除偶然命中）。

## 方法二：动态跟踪（静态失败时）

1. x64dbg 附加游戏进程，在资源加载 API（CreateFile/ReadFile）下断；
2. 定位读取 `*_info.psb.m` 后的解密调用点（AES/MT19937 特征常量、
   `CryptMagic` 类符号），观察传入的密钥缓冲区内容；
3. 提取后按方法一第 4 步验证。

FreeMote 工具链的 `-k` 参数走同一密钥模型（`FreeMote Shell -k <基础串>`），
两种工具解密结果一致可互为验证。

## 提取后的使用方式

按优先级任选其一（`tools/mzs_decrypt.py` 支持三种）：

1. 命令行参数：`--key <BASE_KEY>`
2. 环境变量：`MZS_BASE_KEY`
3. 本地文件：`tools/mzs_key.txt`（仅一行密钥；已被 .gitignore 排除，
   **切勿提交到版本库或分享给他人**）

## 法律与伦理边界（非法律意见）

- 仅对你合法拥有的游戏副本、为个人研究/互操作目的使用；
- 不要把密钥写进任何公开代码、issue、截图或文档——这是本仓库
  资产政策（ASSETS_POLICY.md）的红线之一；
- 密钥本身属于游戏厂商的技术保护措施信息，再分发可能落入
  "规避技术保护措施"的范畴，风险自担。
